# rocq-comparator-web

Browser front-end for `rocq-comparator`, modelled on
[comparator.live.lean-lang.org](https://comparator.live.lean-lang.org) but for
Rocq: paste a challenge `.v` and a solution `.v`, click **Run**, and get the
JSON verdict — the whole check runs **client-side**, no server involved.

The default view is deliberately minimal (Lean-style): just the two editors and
a **Run** button. The theorem targets are **auto-detected** from the challenge
(any `Theorem`/`Lemma`/`Corollary`/`Proposition`/`Fact`/`Remark`/`Example`
declaration), so you normally name nothing. Everything else — an explicit
theorem-name override, definition-name holes, permitted axioms, timeout, and the
kernel flags — lives under a single collapsed **Advanced options** panel.

The shipped check runs on a **`wasm_of_ocaml`** build of `rocq-runtime` 9.2 +
the `rocq-comparator` library, hosted in a Web Worker. Two WebAssembly engines
ship — identical builds differing only in the effects backend — and the worker
loads exactly **one**, feature-detected at load:

- **`engine-cps/`** (`--effects=cps`) — the **universal default**: runs in
  **every** browser (Safari, Firefox, older Chrome/Edge) and any Node. `.wasm`
  ~12 MB + ~20 KB JS glue.
- **`engine-jspi/`** (`--effects=jspi`) — a smaller/faster **upgrade** (`.wasm`
  ~5 MB) loaded only where the JS Promise Integration API exists
  (`WebAssembly.Suspending`): **Chrome/Edge ≥ 137, Node 24+**.

All kernel-level checks (the strict AST filter, in-kernel statement comparison,
dependency-closure and canonical-name matching, assumption analysis by
constructor, universe/flags) run in the browser — the guarantees are the
comparator's real ones, not a text-level approximation. There is **no**
`js_of_ocaml` backend. See `BACKEND.md` for the full design and §15 for how the
WASM runtime was built.

**Prelude:** the build now ships the **Corelib prelude** `.vo` bundle
(`dist/coqlib/`, ~6 MB) — regenerated by a coerce-32bit-patched *native* `rocqc`
so the wasm engine can unmarshal it — so proofs use real Gallina *with* `nat`,
`=`, `->` and the tactic language (`induction`, `simpl`, `rewrite`, `auto`, …).
The prelude plugins (`ltac`, `cc`, `firstorder`, `number_string_notation`,
`tauto`) are statically linked into the engine (the wasm build has no Dynlink).
Uncheck the
`-noinit` toggle only for a prelude-free core-Gallina check.

A **Stdlib subset** is also bundled (`From Stdlib Require Import ZArith / QArith /
Reals / Lia / Lra`, ~28 MB), so `ring`, `field`, `lia`, `lra` over `Z`, `Q`, `R`
check in-browser (all 16 stdlib plugins statically linked).

**mathcomp / mathcomp-analysis** are assessed but **not bundled**: mathcomp core
is ~101 MB / 78 `.vo` and analysis (not installed) adds ~100 MB+, so the full
demo is a ~200 MB+ `.vo` payload — impractical to fetch in a Pages page. The
mechanism is fine (Coq-Elpi/HB wasm-compiles), so the recommended path is
lazy-loading layered packs hosted off Pages. See `BACKEND.md` §14. If the engine
is absent entirely, the page still loads and the **demo-verdict** buttons work.

## Quick start

```sh
make serve      # assemble dist/ and serve it on http://localhost:8000/
```

Then open <http://localhost:8000/>. Use a different port with
`make serve PORT=9000`.

## Building

Two independent builds:

```sh
make site       # assemble dist/ from the committed frontend + engines
                #   -> fast, needs NO opam switch. This is what CI runs.
make real       # (re)build BOTH wasm engines (dist/engine-cps + dist/engine-jspi,
                #   each glue .js + .assets/code-*.wasm) — needs the opam switch.
make test       # node judge harness against BOTH engines -> 12 passed, 0 failed each
make test-browser # serve dist/ and run it in a headless Brave/Chrome/Edge (DevTools
                #   protocol, no npm deps): runtime ready, no 404s, Run button verdict,
                #   Stdlib proof, rejections; once as shipped and once on /?engine=cps
make build      # just type-check/compile the OCaml seam (dune build)
make help       # list all targets
```

`make real` runs `web/build-real.sh`, which rebuilds *only* the kernel/lib/clib
bytecode archives with the coerce-32bit choice (Int64-backed
`uint63_31`/`float64_31`) plus small read-side patches, overlays them via
`OCAMLPATH`, then runs `wasm_of_ocaml` over the seam bytecode — the sibling core
switch's installed rocq-runtime is never modified. It requires that switch
(wasm_of_ocaml + binaryen + rocq-runtime 9.2 sources); override with
`make real SWITCH=...`. It compiles the seam bytecode once and runs
`wasm_of_ocaml` over it **twice** — `--effects=cps` → `dist/engine-cps/` and
`--effects=jspi` → `dist/engine-jspi/`. The custom C primitives the rocq-runtime
references (float64, threads, VM init, getpid, and ~30 zarith `ml_z_*`) are
supplied as WebAssembly in `web/rocq_shims.wat` — wasm_of_ocaml resolves C
primitives from the WASM runtime only, so a JS `//Provides` shim does **not**
work; the zarith stubs delegate arbitrary-precision arithmetic to JS `BigInt`
helpers (`web/rocq_zarith.js`). Both engines (glue + `.wasm`) plus the shared
`rocq_bytes.js` / `rocq_zarith.js` are build artifacts you commit, so CI /
GitHub Pages need not rebuild them.

**Browser support & engine selection.** `web/rocq_worker.js` feature-detects
`WebAssembly.Suspending` at load and loads `engine-jspi/` when present
(Chrome/Edge ≥ 137, Node 24+), else the universal `engine-cps/` (Safari,
Firefox, older Chrome/Edge, any Node). Each visitor fetches exactly **one**
engine. Both are single-threaded (no SharedArrayBuffer / wasm threads), so they
need **no** COOP/COEP headers and run on GitHub Pages as-is (Pages serves
`.wasm` as `application/wasm`).

## Serving it

**Serve `dist/`, not the repo root.** `make serve` is the one supported way: it
runs `make site` (assembling `dist/`) and serves **that directory**.

```sh
make serve                 # == make site && (cd dist && python3 -m http.server 8000)
# or, after `make site`, any static server rooted at dist/:
cd dist && python3 -m http.server 8000     # then open http://localhost:8000/
```

`index.html`, `app.js`, `styles.css` at the repo root are **sources** that
`make site` copies into `dist/`; the engine loader (`rocq_comparator.js`), the
worker (`rocq_worker.js`), the shared glue (`rocq_bytes.js` / `rocq_zarith.js`)
and the engines (`engine-cps/`, `engine-jspi/`) live under `dist/` only. So
serving the **repo root** yields a page whose loader 404s and the check
is disabled. The app now says so precisely: if `window.RocqComparator` never
installs it reports "serving the source tree — serve `dist/` with `make serve`",
and if the worker/engine fails to load it shows the actual error plus the same
fix. `dist/` is a plain static site (no server-side code), and all worker/engine
URLs are **relative**, so it also works unchanged under a sub-path
(`…/<repo>/`).

A same-origin HTTP server is required for the **live** check because the engine
loads in a Web Worker (`new Worker('rocq_worker.js')`), and browsers block
worker creation from `file://`. Opening `dist/index.html` directly as a
`file://` URL still shows the full UI and the **demo-verdict** buttons (which
need no worker) — only the live check needs the server.

The engines are single-threaded WebAssembly (no `SharedArrayBuffer`, no wasm
threads), so they need **no** special COOP/COEP headers.

## Deploying to GitHub Pages

The site is static and all asset paths are **relative**, so it deploys to a
project page (`https://<user>.github.io/<repo>/`) unchanged — no `<base>` tag or
path rewriting.

**Automatic (recommended).** `.github/workflows/pages.yml` deploys on every push
to `main` (and via *Actions → Deploy to GitHub Pages → Run workflow*):

1. In the repo, **Settings → Pages → Build and deployment → Source = GitHub
   Actions**.
2. Commit both engine dirs — `dist/engine-cps/` (~12 MB `.wasm`) and
   `dist/engine-jspi/` (~5 MB `.wasm`), each well under GitHub's 100 MB/file
   limit — so the live check ships. If you skip them, the page still deploys and
   works in demo-verdict-only mode (a workflow warning notes this).
3. Push to `main`. The workflow runs `make site` (assembles `dist/` from the
   committed sources; it does **not** rebuild the engines — that needs the opam
   switch and is not feasible on a stock runner), then publishes `dist/` via
   `actions/upload-pages-artifact` + `actions/deploy-pages`.

**Manual alternative.** Assemble and push `dist/` to a `gh-pages` branch:

```sh
make site
cd dist && git init -b gh-pages && git add -A && git commit -m "site" \
  && git push -f <remote-url> gh-pages
```

Then **Settings → Pages → Source = Deploy from a branch → `gh-pages` / `(root)`**.
`make site` writes a `.nojekyll` into `dist/` so Jekyll does not touch the files.

**Headers.** The WASM engine is single-threaded (no threads / `SharedArrayBuffer`),
so it needs **no** COOP/COEP headers and runs on GitHub Pages as-is. Pages serves
the `.wasm` as `application/wasm` by extension. (A future threaded build using
`SharedArrayBuffer` *would* need `Cross-Origin-Opener-Policy: same-origin` +
`Cross-Origin-Embedder-Policy: require-corp`, unavailable on Pages — but that is
not this build.)

## Files

Front-end (static):
- `index.html` — page structure: minimal default view (two source editors + a
  Run button + verdict panel), a dismissible engine-honesty note, and a
  collapsed **Advanced options** panel with the rest of the config.
- `styles.css` — styling (light/dark aware, responsive to ~400px).
- `app.js` — behaviour: editor gutters, theorem-name auto-detection, request
  assembly, `window.RocqComparator.check`, verdict rendering, and the precise
  backend-unavailable / demo-verdict fallback.
- `examples/` — a sample config and two demo verdicts (also inlined in `app.js`).

`make site` also copies `BACKEND.md` (and `README.md`) into `dist/` so the
in-page note's link to `BACKEND.md` resolves when the site is served.

Backend (built into `dist/` by `web/build-real.sh`):
- `web/web_check.ml` — the seam that installs `RocqComparator`; compiled to
  bytecode, then run through `wasm_of_ocaml` once per effects backend.
- `web/rocq_shims.wat` — the custom C primitives supplied as WebAssembly for the
  WASM build (float64, threads, VM init, getpid, and the zarith `ml_z_*`).
- `web/rocq_bytes.js` — the **byte-exact** `mount()` conversion (`Uint8Array` →
  binary string via `String.fromCharCode`), shared by the worker and the node
  test. Never uses `TextDecoder`, whose WHATWG `latin1` is windows-1252 and
  corrupts binary `.vo` bytes `0x80–0x9F` (the Prelude.vo `Bytes.create` bug).
- `web/rocq_zarith.js` — the JS `BigInt` backend the wasm zarith stubs call.
- `web/patches/coerce-wasm-readside.pl` — small read-side rocq-runtime patches
  the VFS needs (loadpath scan via `Sys.is_directory`; absolute-path
  canonicalisation) — no effect on `.vo` or the native build.
- `web/rocq_worker.js` — the Web Worker that hosts the engine; feature-detects
  JSPI and loads `engine-jspi/` or `engine-cps/` accordingly. Open the page as
  `/?engine=cps` (or `jspi`) to force one variant.
- `web/rocq_comparator.js` — the main-thread loader (`window.RocqComparator`,
  call serialisation, hard kill-timeout, worker respawn).
- `web/build-real.sh` — the one-shot reproducible build of both engines.
- `dist/engine-cps/` and `dist/engine-jspi/` — each `rocq_engine.js` glue +
  `rocq_engine.assets/code-*.wasm`; plus `dist/rocq_bytes.js` /
  `dist/rocq_zarith.js` — the built WASM engine artifacts.

Packaging:
- `Makefile` — `site` / `serve` / `real` / `test` / `test-browser` / `build` targets.
- `.github/workflows/pages.yml` — GitHub Pages deploy workflow.

## Frontend ↔ backend contract

`window.RocqComparator = { ready: Promise, check(requestJson): Promise<string>,
version }`. Request/response are JSON encodings of `{ config, files }` and of the
core `src/verdict.ml` `to_json`. The exact shapes are frozen in `BACKEND.md`
section 6 (and the header of `app.js`). This webapp never modifies the
`rocq-comparator` OCaml project; it consumes it as a library.
