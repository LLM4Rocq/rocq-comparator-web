# rocq-comparator-web

Browser front-end for `rocq-comparator`, modelled on
[comparator.live.lean-lang.org](https://comparator.live.lean-lang.org) but for
Rocq: paste a challenge `.v` and a solution `.v`, name the theorems and
permitted axioms, click **Run**, and get the JSON verdict — the whole check
runs **client-side**, no server involved.

The check runs on a `js_of_ocaml` build of `rocq-runtime` 9.2 + the
`rocq-comparator` library, hosted in a Web Worker. All kernel-level checks (the
strict AST filter, in-kernel statement comparison, dependency-closure and
canonical-name matching, assumption analysis by constructor, universe/flags) run
in the browser — the guarantees are the comparator's real ones, not a
text-level approximation. See `BACKEND.md` for the full design and §11 for how
the in-browser runtime was built.

**Current limitation:** the build runs with `-noinit` — no Corelib prelude
`.vo` bundle is shipped yet (native `.vo` cannot be unmarshalled by jsoo; they
must be regenerated by a patched compiler — `BACKEND.md` §11.5). So proofs use
core Gallina only (`forall`/`fun`, no prelude notations like `->`/`=`, no
`nat`). The pipeline is otherwise complete. If the engine is absent entirely,
the page still loads and the **demo-verdict** buttons work.

## Quick start

```sh
make serve      # assemble dist/ and serve it on http://localhost:8000/
```

Then open <http://localhost:8000/>. Use a different port with
`make serve PORT=9000`.

## Building

Two independent builds:

```sh
make site       # assemble dist/ from the committed frontend + engine
                #   -> fast, needs NO opam switch. This is what CI runs.
make real       # (re)build dist/rocq_engine.js — the js_of_ocaml engine itself
                #   -> needs the opam switch with rocq-runtime 9.2 sources
make test       # node judge harness against the engine -> 7 passed, 0 failed
make build      # just type-check/compile the OCaml seam (dune build)
make help       # list all targets
```

`make real` runs `web/build-real.sh`, which rebuilds *only* the kernel bytecode
archive with the coerce-32bit choice (Int64-backed `uint63_31`/`float64_31`) and
overlays it via `OCAMLPATH` — the sibling core switch's installed rocq-runtime is
never modified. It requires that switch (js_of_ocaml + rocq-runtime 9.2 sources);
override with `make real SWITCH=...`. The resulting `dist/rocq_engine.js` (~28 MB)
is a build artifact you commit, so that CI / GitHub Pages need not rebuild it.

## Serving it

`dist/` is a plain static site — no server-side code. Any static file server
works; `make serve` uses Python's:

```sh
make serve                 # == cd dist && python3 -m http.server 8000
# or directly:
cd dist && python3 -m http.server 8000     # then open http://localhost:8000/
```

A same-origin HTTP server is required for the **live** check because the engine
loads in a Web Worker (`new Worker('rocq_worker.js')`), and browsers block
worker creation from `file://`. Opening `dist/index.html` directly as a
`file://` URL still shows the full UI and the **demo-verdict** buttons (which
need no worker) — only the live check needs the server.

The engine is pure `js_of_ocaml` (no WebAssembly, no `SharedArrayBuffer`), so it
needs **no** special COOP/COEP headers.

## Deploying to GitHub Pages

The site is static and all asset paths are **relative**, so it deploys to a
project page (`https://<user>.github.io/<repo>/`) unchanged — no `<base>` tag or
path rewriting.

**Automatic (recommended).** `.github/workflows/pages.yml` deploys on every push
to `main` (and via *Actions → Deploy to GitHub Pages → Run workflow*):

1. In the repo, **Settings → Pages → Build and deployment → Source = GitHub
   Actions**.
2. Commit `dist/rocq_engine.js` (~28 MB — well under GitHub's 100 MB/file limit)
   so the live check ships. If you skip it, the page still deploys and works in
   demo-verdict-only mode (a workflow warning notes this).
3. Push to `main`. The workflow runs `make site` (assembles `dist/` from the
   committed sources; it does **not** rebuild the engine — that needs the opam
   switch and is not feasible on a stock runner), then publishes `dist/` via
   `actions/upload-pages-artifact` + `actions/deploy-pages`.

**Manual alternative.** Assemble and push `dist/` to a `gh-pages` branch:

```sh
make site
cd dist && git init -b gh-pages && git add -A && git commit -m "site" \
  && git push -f <remote-url> gh-pages
```

Then **Settings → Pages → Source = Deploy from a branch → `gh-pages` / `(root)`**.
`make site` writes a `.nojekyll` into `dist/` so Jekyll does not touch the files.

**Headers caveat.** The current engine needs no special headers. A *future*
`wasm_of_ocaml` build using threads / `SharedArrayBuffer` would require
`Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy:
require-corp`, which **GitHub Pages cannot set**. Workarounds then: the
[`coi-serviceworker`](https://github.com/gzuidhof/coi-serviceworker) shim, or a
host that can set headers (Netlify/Cloudflare Pages/Vercel). Not needed today.

## Files

Front-end (static):
- `index.html` — page structure: two source editors, config form, verdict panel.
- `styles.css` — styling (light/dark aware, responsive to ~400px).
- `app.js` — behaviour: editor gutters, request assembly,
  `window.RocqComparator.check`, verdict rendering, and the backend-unavailable
  / demo-verdict fallback.
- `examples/` — a sample config and two demo verdicts (also inlined in `app.js`).

Backend (built into `dist/` by `web/build-real.sh`):
- `web/web_check.ml` — the js_of_ocaml seam (installs `RocqComparator`).
- `web/runtime_shims.js`, `web/zarith_stubs.js` — jsoo runtime primitives.
- `web/rocq_worker.js` — the Web Worker that hosts the engine.
- `web/rocq_comparator.js` — the main-thread loader (`window.RocqComparator`,
  call serialisation, hard kill-timeout, worker respawn).
- `web/build-real.sh` — the one-shot reproducible engine build.
- `dist/rocq_engine.js` — the built engine artifact.

Packaging:
- `Makefile` — `site` / `serve` / `real` / `test` / `build` targets.
- `.github/workflows/pages.yml` — GitHub Pages deploy workflow.

## Frontend ↔ backend contract

`window.RocqComparator = { ready: Promise, check(requestJson): Promise<string>,
version }`. Request/response are JSON encodings of `{ config, files }` and of the
core `src/verdict.ml` `to_json`. The exact shapes are frozen in `BACKEND.md`
section 6 (and the header of `app.js`). This webapp never modifies the
`rocq-comparator` OCaml project; it consumes it as a library.
